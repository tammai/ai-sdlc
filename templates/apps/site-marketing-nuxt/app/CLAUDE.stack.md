- Commands: `pnpm dev` (serves `media/` at `/media`) · `pnpm dev:worker` (build, seed local R2 from `media/`, `wrangler dev`: the closest thing to production) · `pnpm run typecheck` · `pnpm run lint` · `pnpm run test` (offline) · `pnpm run build` (`nuxt generate`, output in `.output/public`).
- Nuxt 4 static site, prerendered at build time (`ssr: true` + `nuxt generate`; no runtime page rendering, no API, no Nitro routes) + Nuxt UI/Tailwind v4 + Nuxt Content 3. This is the one place a site differs from the app templates, which run `ssr: false`: a site needs real HTML for search engines and link previews.
- Content: Markdown in `content/`. `content/<name>.md` renders at `/<name>` (`app/pages/[...slug].vue`); `content/blog/<name>.md` at `/blog/<name>`. Frontmatter is validated by `content.config.ts` at build (a bad date or missing title fails `pnpm run build`). Header and footer links are `nav` in `app/data/site.ts`; a test checks each one has a page. Drafts are files in `content/blog/drafts/`: previewed in `pnpm dev`, excluded from production builds entirely. Never use a `draft: true` flag: on static hosting the browser downloads the whole collection (`/__nuxt_content/<collection>/sql_dump.txt`), so a flagged post's text would still be public. The same goes for anything embargoed: don't put it in `content/` until it is meant to be public.
- Media is in R2, never in git or the build: `/media/<key>` is served by `worker/index.ts` (GET/HEAD, ranges, ETag/304, colo cache) from the `MEDIA` bucket, and only that path runs the Worker (`run_worker_first` in `wrangler.jsonc`), so pages stay static. Refer to a file by key: `![alt](/media/blog/x.webp)` in Markdown, `<MediaImage src="blog/x.webp" alt="…" />` in a component, `image: blog/x.webp` in frontmatter. Alt text is required. Keys use letters, digits and `._~-` with `/` between folders; replace a cached file under a new key.
- `media/` in the project is a small local sample set only (`pnpm dev`, and `pnpm media:seed` copies it into the LOCAL bucket). Uploading to the real bucket (`wrangler r2 object put <bucket>/<key> --file … --remote`, `wrangler r2 object delete`) changes production and needs a human; always pass `--local` or `--remote`, never rely on the default. Create each env's bucket once with `wrangler r2 bucket create`.
- Deploy: `wrangler deploy --env staging` is the preview; `--env production` needs a human. Set `NUXT_PUBLIC_SITE_URL` to the real origin at build time (sitemap URLs) and update `public/robots.txt`.
- Ship only what the site uses: Nuxt UI components are auto-imported, so only the ones a page renders end up in the bundle (use them by name, don't register the library globally); `ui.experimental.componentDetection` is on, so CSS is generated only for components a page renders; a component chosen at runtime (`<component :is>`) must be listed there. Icons are `i-lucide-*` from the local `@iconify-json/lucide`, and `icon.clientBundle.scan` bundles just the ones in use. Code blocks only highlight the languages listed in `content.build.markdown.highlight.langs`. Don't turn `icon.fallbackToApi` back on (it makes the browser call a third-party API).
- Copy comes from the user's brief (the intent doc when there is one); never invent metrics, customer logos, testimonials or prices. Site name, nav and the home page text are in `app/data/site.ts`; the other pages are `content/*.md`. `site.contactEmail` ships as `hello@example.com` and must be replaced before deploy. There is no form backend: contact is a `mailto:` link.
- Links between pages are crawled at build time and a broken one fails `pnpm run build`. Links under `/media` are not checked (they are not prerendered).
