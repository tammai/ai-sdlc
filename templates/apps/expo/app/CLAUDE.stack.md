- Commands: `pnpm start` (Expo dev server) · `pnpm typecheck` · `pnpm lint` · `pnpm test` (jest-expo, offline) · `pnpm gen:api` (regenerates `src/api/schema.d.ts` from `../contracts/openapi.yaml`) · `pnpm expo:doctor` (expo-doctor; part of verify, tolerates being offline).
- Layout: `src/app` expo-router routes only (thin; typed routes) · `src/features/<f>` screens + hooks · `src/api` openapi-fetch client (Bearer + single-flight 401 refresh) · `src/auth` token store (expo-secure-store), sign-in flows · `src/ui` + `src/theme.ts` tokens.
- Auth is native bearer tokens against the Go API (`/v1/auth/token`, rotating refresh). Sign-in/sign-up UI is driven by `GET /v1/auth/providers`; native OIDC uses PKCE (S256, verifier kept in memory only). Deep links `<scheme>://auth/magic?token=…` and `<scheme>://auth/callback?code=…` (scheme = app slug in `app.json`/`src/config.ts`).
- API base URL: `EXPO_PUBLIC_API_URL` (Android emulator: `http://10.0.2.2:8080`; device: LAN IP). Never edit `src/api/schema.d.ts`; change the contract and regenerate.
- Managed workflow: no `ios/`/`android/` folders; native builds via EAS or `expo prebuild`. Set real bundle ids (placeholder `com.example.app`) in `app.json` before any store build.
- Tokens only in expo-secure-store, never AsyncStorage/logs. Every screen handles loading (skeleton), error (retry) and empty; touch targets ≥ 44pt, `accessibilityLabel` on icon buttons, colors from `useTheme()` (dark mode via `useColorScheme`).
