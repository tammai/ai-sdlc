# Profile: edge-web — full-stack on Cloudflare Workers

**Default:** Nuxt 4 · Nuxt UI · Tailwind v4 · Nitro `cloudflare_module` preset · D1 (SQL) + KV (cache/flags/sessions-lite) + R2 (files) · Drizzle ORM · Zod · `ssr: false`.
**React variant:** Next.js (App Router) · shadcn/ui · Tailwind v4 · OpenNext Cloudflare adapter (`@opennextjs/cloudflare`) · same bindings · client-rendered pages, route handlers as the server.

## Layout (Nuxt)
```
app/            pages/, components/, composables/, layouts/   (client only — ssr: false)
server/api/     route handlers — the only server code; validate every body/query with Zod
server/db/      schema.ts (Drizzle), migrations/ (generated by drizzle-kit — protected)
server/utils/   db(event), kv(event), r2(event) helpers reading event.context.cloudflare.env
shared/         types + Zod schemas shared by app and server
wrangler.jsonc  bindings: d1_databases[DB], kv_namespaces[KV], r2_buckets[BUCKET]; env.staging / env.production
```
Next variant: `app/` routes are `'use client'` pages; `app/api/**/route.ts` are the server; bindings via `getCloudflareContext().env`.

Note: `create-cloudflare --framework=next` now generates a vinext (Vite-based) app by default. This profile and its template use `create-next-app` with `@opennextjs/cloudflare`. OpenNext's build needs symlinks, so on Windows without Developer Mode, run `pnpm build` in WSL.

## Rules
- Data access only in server routes; the client calls `/api/*` with `$fetch`/`useFetch` (Nuxt) or TanStack Query (Next). No secrets or bindings in client code.
- Auth: `nuxt-auth-utils` sealed-cookie sessions (Nuxt) / Better Auth with the D1 Drizzle adapter (Next). Every non-public route calls `requireUserSession(event)` (or equivalent) first.
- D1: migrations via `drizzle-kit generate` → `wrangler d1 migrations apply DB --local` in dev. Remote apply is a production action (gated). Batch writes with `db.batch()`; no long transactions.
- KV is eventually consistent — never the source of truth for anything you read-after-write. R2: presigned/streamed uploads, store object keys in D1.
- Secrets: `wrangler secret put` (gated) / `.dev.vars` locally (secret path — the guard blocks reading it).
- UI: Nuxt UI / shadcn components first; Tailwind utilities, no custom CSS unless a token is missing. Every async view has empty/loading/error states.

## Tests & verify
Vitest (+ `@nuxt/test-utils` for Nuxt) for server routes and composables (D1 via Miniflare/local bindings); Playwright for 1–3 critical e2e flows. Verify preset: typecheck · lint · test · build.

## Deploy
Preview: `wrangler versions upload` / `wrangler deploy --env staging` (agent may run). Production: `wrangler deploy` (prod gate) from CI on merge to main. Rollback: `wrangler rollback` (rehearse it).

## Scaffold
`sdlc scaffold-app` copies the verified template for this profile (`templates/apps/`). The notes below describe how the template was built — use them only when adding this profile's pieces by hand.
Nuxt: `pnpm create nuxt@latest <name>` → add `@nuxt/ui`, `drizzle-orm`, `drizzle-kit`, `zod`, `nuxt-auth-utils`, `@nuxt/eslint`, `@nuxt/test-utils`, `vitest`, `wrangler`; `nuxt.config.ts`: `ssr: false`, `nitro: { preset: 'cloudflare_module' }`; local bindings via `nitro-cloudflare-dev` (or Nitro's built-in Cloudflare dev emulation if available in your version). Scripts: `typecheck` (`nuxt typecheck`), `lint`, `test` (`vitest run`), `build`.
Next: `pnpm create cloudflare@latest <name> --framework=next` (OpenNext) → shadcn init, Drizzle, Zod, Better Auth.

## CLAUDE.md snippet
- Stack: Nuxt 4 SPA (ssr:false) + Nitro server routes on Cloudflare Workers; D1 via Drizzle, KV, R2. UI: Nuxt UI + Tailwind v4.
